# Design Patterns

## What Are Design Patterns?

Reusable solutions to common design problems. A shared vocabulary for discussing design. Many classic patterns are built into Kotlin as language features - prefer the idiom over a hand-rolled pattern.

## WARNING: Don't Force Patterns

> "Let patterns emerge from refactoring, don't force them upfront."

Patterns should solve problems you HAVE, not problems you MIGHT have.

## When to Use Patterns

1. **You recognize the problem** - You've seen it before
2. **The pattern fits** - Not forcing it
3. **It simplifies** - Doesn't add unnecessary complexity
4. **Team understands it** - Shared knowledge

## Creational Patterns

### Singleton

**Purpose:** Ensure only one instance exists.

**Kotlin idiom:** `object` for stateless singletons; a **singleton scope in the DI container** for anything with dependencies or state (databases, repositories, HTTP clients).

**Warning:** Hidden global state hurts testability. Never reach for a singleton from inside a class - inject it.

```kotlin
// Stateless utility-like singleton: fine as an object
object PriceFormatter {
    fun format(amount: Money, locale: Locale): String = /* ... */
}

// Stateful or with dependencies: one instance, provided by DI and injected
class DefaultSessionRepository(
    private val sessionLocalDataSource: SessionLocalDataSource,
) : SessionRepository
```

### Factory

**Purpose:** Create objects without specifying the exact class.

**Kotlin idiom:** factory functions (top-level or in a `companion object`), and `ViewModelProvider.Factory` for ViewModels with dependencies when DI doesn't generate it.

```kotlin
sealed interface Notification {
    fun send(message: String)
}

fun createNotification(channel: NotificationChannel): Notification = when (channel) {
    NotificationChannel.Email -> EmailNotification()
    NotificationChannel.Sms -> SmsNotification()
    NotificationChannel.Push -> PushNotification()
}

// Named factory in a companion
data class Point(val x: Double, val y: Double) {
    companion object {
        fun fromPolar(radius: Double, angle: Double): Point = Point(radius * cos(angle), radius * sin(angle))
    }
}

// ViewModel factory (when not generated by a DI library)
class ProfileViewModel(private val userRepository: UserRepository) : ViewModel() {
    companion object {
        val Factory: ViewModelProvider.Factory = viewModelFactory {
            initializer { ProfileViewModel((this[APPLICATION_KEY] as MyApplication).container.userRepository) }
        }
    }
}
```

### Builder

**Purpose:** Construct complex objects step by step.

**Kotlin idiom:** default parameters + named arguments make most builders unnecessary. Use type-safe DSLs (`buildList`, `buildString`, `buildAnnotatedString`) when building incrementally.

```kotlin
// Instead of a UserBuilder
data class User(
    val name: String,
    val email: Email,
    val age: Int? = null,
    val isNewsletterSubscribed: Boolean = false,
)

val user = User(name = "Alice", email = Email("alice@example.com"))

// Incremental building
val visibleActions = buildList {
    add(Action.Share)
    if (canEdit) add(Action.Edit)
}
```

### Prototype

**Purpose:** Create new objects by copying existing ones.

**Kotlin idiom:** `data class` `copy()`.

```kotlin
val draft = Document(title = "Report", content = "", metadata = Metadata(author = "Ana"))
val updatedDraft = draft.copy(content = "New content")
```

## Structural Patterns

### Adapter

**Purpose:** Make incompatible interfaces work together.

**Android use:** data sources adapt third-party SDKs and APIs to your own interfaces; `callbackFlow` adapts callback APIs to `Flow`; mappers adapt network/database models to app models.

```kotlin
// Third-party SDK with a different interface
class LegacyPaymentSdk {
    fun makePayment(cents: Long, callback: (Boolean) -> Unit) { /* ... */ }
}

// Our interface
interface PaymentGateway {
    suspend fun charge(amount: Money): ChargeResult
}

// Adapter
class LegacyPaymentGateway(private val legacySdk: LegacyPaymentSdk) : PaymentGateway {
    override suspend fun charge(amount: Money): ChargeResult = suspendCancellableCoroutine { continuation ->
        legacySdk.makePayment(amount.toCents()) { isSuccessful ->
            continuation.resume(if (isSuccessful) ChargeResult.Success else ChargeResult.Failed)
        }
    }
}
```

### Decorator

**Purpose:** Add behavior to objects dynamically.

**Android use:** a caching or logging repository wrapping another implementation; HTTP client interceptors (e.g. OkHttp) decorating requests. Kotlin class delegation (`by`) keeps decorators short.

```kotlin
class CachingNewsRepository(
    private val delegate: NewsRepository,
) : NewsRepository by delegate {

    private val cacheMutex = Mutex()
    private var cachedNews: List<Article>? = null

    override suspend fun getLatestNews(): List<Article> = cacheMutex.withLock {
        cachedNews ?: delegate.getLatestNews().also { latestNews -> cachedNews = latestNews }
    }
}
```

### Proxy

**Purpose:** Control access to an object.

**Kotlin idiom:** `by lazy` for lazy initialization; DI `Lazy<T>`/`Provider<T>` for deferring expensive creation.

```kotlin
class ImageViewerController(private val imagePath: String) {
    private val decodedImage: Bitmap by lazy { decodeFromDisk(imagePath) } // expensive, created on first use

    fun display(target: ImageTarget) = target.show(decodedImage)
}
```

### Composite

**Purpose:** Treat individual objects and compositions uniformly.

**When to use:** Tree structures, hierarchies (files/folders, menus). Compose UI itself is a composite.

```kotlin
sealed interface CartComponent {
    val price: Money
}

data class Product(override val price: Money) : CartComponent

data class Bundle(val children: List<CartComponent>) : CartComponent {
    override val price: Money get() = children.fold(Money.ZERO) { sum, child -> sum + child.price }
}

val bigBundle = Bundle(listOf(Bundle(listOf(Product(Money.of(10)), Product(Money.of(20)))), Product(Money.of(50))))
bigBundle.price // 80
```

## Behavioral Patterns

### Strategy

**Purpose:** Define a family of algorithms and make them interchangeable.

**Kotlin idiom:** a `fun interface`, or a plain function type when the strategy is a single operation.

```kotlin
fun interface PricingStrategy {
    fun calculate(basePrice: Money): Money
}

val regularPricing = PricingStrategy { basePrice -> basePrice }
val premiumDiscount = PricingStrategy { basePrice -> basePrice * PREMIUM_MULTIPLIER }

class ShoppingCart(private val pricingStrategy: PricingStrategy) {
    fun calculateTotal(items: List<CartItem>): Money {
        val basePrice = items.fold(Money.ZERO) { sum, item -> sum + item.price }
        return pricingStrategy.calculate(basePrice)
    }
}
```

### Observer

**Purpose:** Notify multiple objects about state changes.

**Kotlin/Android idiom:** `Flow`, `StateFlow`, `SharedFlow` (or `LiveData` where the project uses it). Don't hand-roll observer lists.

```kotlin
class OrderRepository(/* ... */) {
    private val _placedOrders = MutableSharedFlow<Order>()
    val placedOrders: SharedFlow<Order> = _placedOrders.asSharedFlow()

    suspend fun placeOrder(order: Order) {
        // persist...
        _placedOrders.emit(order)
    }
}

// Observer
orderRepository.placedOrders.collect { order -> sendConfirmation(order) }
```

UI state is observed as `StateFlow` with lifecycle awareness (see [ui-layer.md](ui-layer.md)).

### Template Method

**Purpose:** Define an algorithm skeleton and let subclasses override steps.

**Android use:** framework classes already use it (`CoroutineWorker.doWork()`, `ViewModel.onCleared()`). Use it sparingly in your own code - composition (Strategy) is usually clearer.

```kotlin
abstract class DataExporter {
    // Template method - defines the algorithm
    suspend fun export(records: List<Record>) {
        validate(records)
        val formattedContent = format(records)
        write(formattedContent)
    }

    private fun validate(records: List<Record>) = require(records.isNotEmpty()) { "Nothing to export" }

    // Steps to override
    protected abstract fun format(records: List<Record>): String
    protected abstract suspend fun write(content: String)
}

class CsvExporter(private val fileWriter: FileWriter) : DataExporter() {
    override fun format(records: List<Record>): String = records.joinToString("\n") { record -> record.toCsvLine() }
    override suspend fun write(content: String) = fileWriter.write(EXPORT_FILE_NAME, content)
}
```

### Command

**Purpose:** Encapsulate a request as an object.

**Android use:** a `sealed interface` of UI actions handled by a single ViewModel function; undo/redo stacks.

```kotlin
sealed interface CartAction {
    data class AddItem(val item: CartItem) : CartAction
    data class RemoveItem(val itemId: ItemId) : CartAction
    data object Clear : CartAction
}

class CartViewModel : ViewModel() {
    private val _uiState = MutableStateFlow(CartUiState())
    val uiState: StateFlow<CartUiState> = _uiState.asStateFlow()

    fun onAction(action: CartAction) {
        _uiState.update { currentState ->
            when (action) {
                is CartAction.AddItem -> currentState.copy(items = currentState.items + action.item)
                is CartAction.RemoveItem -> currentState.copy(items = currentState.items.filterNot { item -> item.id == action.itemId })
                CartAction.Clear -> currentState.copy(items = emptyList())
            }
        }
    }
}
```

Use this only when it makes the code clearer; plain functions (`addItem()`, `removeItem()`) are equally valid and often more readable.

## Compose Patterns

| Pattern | Compose form |
|---------|--------------|
| **Composition over configuration** | Slots: `@Composable` lambda parameters instead of many optional `String?`/`Icon?` parameters |
| **State holder** | `<Component>State` class + `remember<Component>State()` factory |
| **Defaults object** | `<Component>Defaults` exposing default colors, sizes, and paddings |
| **Decorator** | `Modifier` chains and custom `Modifier` extension functions |

```kotlin
@Composable
fun AppTopBar(
    title: @Composable () -> Unit,
    modifier: Modifier = Modifier,
    navigationIcon: @Composable () -> Unit = {},
    actions: @Composable RowScope.() -> Unit = {},
)
```

## Pattern Awareness

### The Four-Dimensional Lens

When analyzing new code/libraries, ask:

1. **What problem does it solve?** (Creational, Structural, Behavioral)
2. **What scope?** (Object-level, Class-level, System-level)
3. **When is it applied?** (Compile-time, Runtime)
4. **How coupled?** (Tight, Loose)

This helps recognize patterns even in unfamiliar code.

## Anti-Patterns to Avoid

| Anti-Pattern | Problem | Solution |
|--------------|---------|----------|
| **God Object / God Activity** | Class does everything | Split by responsibility and layer |
| **Spaghetti Code** | Tangled, no structure | Refactor to layers |
| **Golden Hammer** | Using one pattern (or library) for everything | Match pattern to problem |
| **Premature Optimization** | Optimizing before measuring | YAGNI; profile release builds first |
| **Copy-Paste Programming** | Duplication | Extract, Rule of Three |
| **Service Locator inside classes** | Hidden dependencies (`Injector.get<Repo>()` in a function) | Constructor injection |
